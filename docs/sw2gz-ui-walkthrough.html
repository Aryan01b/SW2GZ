1. What is SW2GZ?

SW2GZ is a SolidWorks add-in that exports an assembly to a ready-to-build ROS 2 package targeting ROS 2 Jazzy + Gz Sim Harmonic. Fork of solidworks_urdf_exporter with ROS 1 / Gazebo Classic support replaced by modern Gz Sim writers.

One export produces:

  • URDF + xacro — robot description.
  • DAE visual meshes — colour-preserved via Collada 1.4.1.
  • STL collision meshes — convex-hull-decimated (AABB in v2.0; QuickHull v2.1).
  • SDF world + Gz launch files — spawns the model in gz sim.
  • ros2_control config — joint_state_broadcaster + joint_trajectory_controller wired in.
  • ros_gz_bridge config — bridges /clock and joint states between Gazebo and ROS 2.
  • package.xml + CMakeLists.txt — colcon-buildable as-is.
Auto-calc: mass, inertia tensor, and centre-of-mass are read from SolidWorks' MassProperty API. No manual entry required, as long as parts have materials assigned.

2. Install + Enable

2.1 Run the installer (admin)

Right-click SW2GZ-Setup-1.0.0.exe → Run as administrator. The installer:

  • Copies SW2GZ.dll + dependencies to C:\Program Files\SW2GZ\.
  • Runs regasm /codebase which registers the COM CLSID {34fad620-2a46-4ba6-9f5f-1dfefde894c7} under HKLM\SOFTWARE\Classes\CLSID.
  • The [ComRegisterFunction] inside the DLL writes the SolidWorks-side key: HKLM\SOFTWARE\SolidWorks\Addins\{34fad620-...} with Title="SW2GZ" and Description="SolidWorks to ROS 2 + Gz Sim Exporter".
SolidWorks must be closed during install. Otherwise the DLL is locked and regasm fails silently.

2.2 Enable inside SolidWorks

Open SolidWorks → Tools → Add-Ins…. Find SW2GZ in the list. Tick both:

  • Active Add-ins — loads it for the current session.
  • Start Up — auto-loads on every SolidWorks start.

Click OK. SW2GZ is now live.

SolidWorks → Tools → Add-Ins

3. Where to Find It

Once enabled, SW2GZ appears as a top-level menu in the SolidWorks menu bar (right of Window).

SolidWorks menu bar

Click SW2GZ to open the dropdown:

  • Assembly Export… — main export workflow (for assemblies)
  • Part Export… — single-part export
  • About — version info
Future: A ribbon-tab integration is planned for Spec #2 (deferred UI overhaul, alongside dark mode + intuitive link/joint adding). v2.0 keeps the upstream menu pattern.

4. Export Wizard

Open an assembly (must be a real assembly file, not a part). SW2GZ → Assembly Export… opens the multi-tab wizard.

4.1 Link tab — build the link tree

The left panel is a tree view representing the URDF link hierarchy. Each branch is a robot link; a robot's base link is the root.

  1. Drag SolidWorks components from the FeatureManager (right) into the tree on the left to assign them to a link.
  2. SW2GZ auto-fills mass, inertia tensor, and centre-of-mass from the SolidWorks MassProperty API. These fields display as read-only.
  3. Pick a visual material colour (carried into the DAE).
  4. Set mesh export format — STL (default) or 3DXML. v2.0 emits DAE for visual + STL for collision regardless of this selection; the radio is vestigial pending Spec #2 UI cleanup.

4.2 Joint tab — define joints between links

  1. Select a child link → its joint properties appear on the right.
  2. Pick joint type: fixed, revolute, continuous, prismatic.
  3. Pick the axis component (a SolidWorks axis or edge).
  4. Optional: set limits (lower/upper/effort/velocity).
Bug 10 warning: If the joint type is continuous but the controller uses a position command interface, the export emits a warning (no limits enforced — arm can spin freely).

4.3 Finish Export

Click Export URDF and Meshes… at the bottom right. A file dialog asks where to save. Pick a directory.

What changed from v1: The dialog previously showed ROS 2 Distro (Humble / Jazzy / Kilted / Rolling) and Gz Version (Fortress / Harmonic / Ionic) combo boxes. v2.0 hard-locks to Jazzy + Harmonic, so those controls were removed. The dialog is now 290 px tall (down from 360 px).

Click OK. The export pipeline runs:

  1. SW Surface phase — walks the assembly, reads mass properties, tessellates meshes (throws MaterialMissingException if any part has no material assigned).
  2. Build phase — sanitizes the package name (hyphens → underscores), builds the convex-hull collision AABB, aggregates sub-assembly inertia via parallel-axis theorem.
  3. Write phase — emits 14+ files (see § 6 below).
  4. Validate phase — runs static lint (package name regex, URDF well-formedness, mesh files exist, plugin class names correct). Errors pop a MessageBox; warnings go into PreExportReport.warnings.txt.

6. Output Package Layout

A successful export produces this tree under <output-dir>/<sanitized-pkg>/:

<pkg>/ ├── package.xml # ros_gz_sim, ros_gz_bridge, gz_ros2_control deps hard-coded ├── CMakeLists.txt # install(DIRECTORY urdf launch config worlds meshes ...) ├── urdf/ │ ├── <pkg>.urdf.xacro # top-level: includes the three .xacro under inc/ │ └── inc/ │ ├── gz.xacro ← v2 (was empty placeholder) │ ├── ros2_control.xacro ← v2 ($(find <pkg>), no $(arg pkg)) │ └── materials.xacro ├── worlds/ │ └── empty.sdf ← v2 (unversioned gz-sim-*-system) ├── launch/ │ ├── gz_sim.launch.py ← v2 (GZ_SIM_SYSTEM_PLUGIN_PATH + parameter_bridge) │ ├── ros2_control.launch.py │ └── display.launch.py ├── config/ │ ├── controllers.yaml # joint_state_broadcaster + joint_trajectory_controller │ ├── ros_gz_bridge.yaml ← v2 (gz_topic includes <pkg>) │ └── rviz.rviz └── meshes/ ├── base_link.dae ← Collada 1.4.1, Z_UP, embedded colour ├── base_link_collision.stl ← binary STL (AABB convex hull) ├── arm1.dae ├── arm1_collision.stl └── ... # one .dae + one _collision.stl per link

7. Running in ROS 2 Jazzy + Gz Sim Harmonic

The output package builds and runs unchanged on a ROS 2 Jazzy system with Gz Sim Harmonic installed. Typical Linux / WSL2 flow:

# 1. Symlink into your workspace
cd ~/ros2_ws/src
ln -s /mnt/d/path/to/<pkg> .

# 2. Build
cd ~/ros2_ws
colcon build --packages-select <pkg>
source install/setup.bash

# 3. Launch Gazebo + the robot + bridge + controllers, all in one
ros2 launch <pkg> gz_sim.launch.py

# 4. In another terminal, verify joint states flowing
ros2 topic echo /joint_states

# 5. Verify both controllers are active
ros2 control list_controllers
#   joint_state_broadcaster        [joint_state_broadcaster/JointStateBroadcaster] active
#   joint_trajectory_controller    [joint_trajectory_controller/JointTrajectoryController] active

# 6. Command the arm
ros2 topic pub /joint_trajectory_controller/joint_trajectory \
  trajectory_msgs/msg/JointTrajectory \
  '{ ... }'   # see ROS 2 docs for the message shape
Acceptance gate (all must be true for v2.0 to be considered shipped):
  • Arm visible in the gz sim window with the correct colour (DAE carry-through).
  • /joint_states publishes (means the bridge is alive).
  • Both controllers report active (means gz_ros2_control loaded).
  • No exceptions in ros2 launch output.

9. Troubleshooting

SW2GZ doesn't appear in the Add-Ins list

  • Reinstall as administrator (the COM CLSID write requires it).
  • Verify the registry key exists: HKLM\SOFTWARE\SolidWorks\Addins\{34fad620-2a46-4ba6-9f5f-1dfefde894c7}
  • Verify SW2GZ.dll sits at C:\Program Files\SW2GZ\SW2GZ.dll.

MaterialMissingException on Export

One or more parts in the assembly have no SolidWorks material assigned (mass returns 0). Pipeline aborts before any files are written. Open the part in SolidWorks → Edit Material → pick one → save → re-export.

colcon build fails with "Package name cannot contain hyphens"

You picked a package name with hyphens. SW2GZ already sanitized it for the internal file content, but check that the directory name on disk also got renamed by the pipeline — the sanitized name is what the dir uses. Re-export with a clean name to be safe.

ros2 launch hangs at "waiting for /controller_manager"

Almost always means gz_ros2_control isn't loaded inside gz sim. Confirm:

  • gz_ros2_control is installed: ros2 pkg list | grep gz_ros2_control
  • libgz_ros2_control-system.so exists at $(ros2 pkg prefix gz_ros2_control)/lib/
  • The launch file's GZ_SIM_SYSTEM_PLUGIN_PATH line is emitted — this is v2.0's bug-5 fix; if you're somehow running a v1 export, hand-edit it.

RViz shows the robot without colour

The DAE writer embeds the SolidWorks part colour in library_effects. If RViz shows grey, the part probably had a generic Default material with no colour assigned. Set a non-default appearance in SolidWorks.

I want the dialog to remember last-used Author/Email/License

Not yet — deferred to Spec #2 (UI overhaul). For v2.0, every export prompts fresh defaults.
