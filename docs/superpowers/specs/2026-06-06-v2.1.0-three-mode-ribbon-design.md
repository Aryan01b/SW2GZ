# SW2GZ v2.1.0 — Three-Mode Ribbon (Robot / World / Asset)

**Status:** Approved design — proceeding to implementation plan
**Date:** 2026-06-06
**Branch:** `v2.1.0` (from `main` HEAD `e0b079a`)
**Supersedes:** the impulsive `Sw2gzExportPmp` linear-wizard shape introduced in v2.1.1.

---

## 1. Problem statement

The current `v2.1.1` codebase ships a working SolidWorks → ROS 2 Jazzy + Gz Harmonic exporter, but the UI is a single linear PropertyManagerPage wizard (`Mode → Links → Joints → Review`). Three problems:

1. **Linear wizard fights the workflow.** Users want to dip into one feature (re-pick joint axis, add a sensor, tweak inertia) without traversing every step. SolidWorks' own **Sketch tab** model — panels of buttons, each opening a focused PMP that edits one piece of doc state — fits the task far better.
2. **The plug-and-play stack is shallow.** SDFormat 1.9 frame graph, `ros2_control` block + controllers.yaml, `ros_gz_bridge` + `/clock` + `use_sim_time`, world `<physics>/<gui>/<light>`, full launch + `model.config` + env vars (`GZ_SIM_RESOURCE_PATH`, `GZ_SIM_SYSTEM_PLUGIN_PATH`) — all needed for "directly run". Current code covers ~40%.
3. **Coordinate-frame handling is user-visible.** The wizard asks the user to pick SW up/forward axes. This is internal plumbing — getting it wrong tilts the spawned robot. Default behaviour must be automatic.

The Robot / World / Asset trichotomy already exists in code as `ExportMode`, but the **UI doesn't present it as three first-class workflows**; it presents it as a single radio button buried inside a wizard step.

## 2. Scope

### In scope (v2.1.0)

- **Three ribbon sections** as panel clusters under a single `SW2GZ` tab:
  - **Robot** — actuated multi-link models (URDF/xacro + ros2_control + gz plugins)
  - **World** — Gz sim worlds (SDF world + included asset models + physics/scene)
  - **Asset** — single-body static SDF models
- **Common cluster** — Mode toggle, Preview, Export. Coord lives in advanced-only.
- **Live, re-entrant PMPs** — each panel button opens a PMP that edits ONE subtree of the doc-attached config. Closing one and opening another never loses prior state.
- **One mode per assembly doc.** Mode tag stored in the SW Attribute; ribbon panels for non-active modes hidden via `OnEnableCallback`.
- **Doc-attached config tree** in a single SolidWorks Attribute feature (`SW2GZ Export Configuration (v1)`), visible in the FeatureManager.
- **Automatic SW→ROS coordinate transform** baked into output by default — no user input required.
- **Robot mode plug-and-play stack:** ros2_control block, controllers.yaml, gz_ros2_control plugin, ros_gz_bridge.yaml (incl. `/clock`), robot_state_publisher, joint_state_broadcaster, launch.py composing world + spawn + bridge + RSP + controllers, package.xml + CMakeLists + env-var setup.
- **World mode:** pick base part (static ground), pick other parts as asset includes, physics (engine/step/RTF), scene (light/sky/gui), optional spherical_coordinates, full SDF world output + launch.
- **Asset mode:** single-part static SDF model + spawn-in-empty-world launch.
- **SDFormat 1.9 frame graph** usage in joint/link `<pose relative_to=…>` semantics.
- **Per-joint controller pick** + **diff_drive preset** (one mobile-base preset only).
- **Existing `SensorKind` set:** Imu, GpuLidar, Camera, DepthCamera, ForceTorque, Contact, Navsat.
- **Cleanup:** remove dead code (`TfTreeFormatter`, `bool emitWorldLink`, back-compat `Sw2gzPipeline.Run` overloads, dual `PoseMath`, unread `PreviewResult` fields, legacy `URDF Export Configuration (v1.4)` attribute reads where they're dead).
- **Naming migration:** remaining `sw2urdf` / `URDF Export` identifiers and resource strings → `sw2gz` / `SW2GZ Export`.

### Out of scope (deferred to ≥ v2.2)

- Multi-mode-per-doc (Robot + World in one assembly).
- Hierarchical World referencing external Robot/Asset asm files.
- Full controller library beyond {position, velocity, effort, joint_trajectory, diff_drive}: no ackermann, mecanum, gripper, admittance.
- Heightmap / DEM / skybox / GUI-plugin selection UI (defaults emitted; manual SDF edit).
- Manual inertia override UI (auto from SW MassProperties only).
- Manual coord-axis picker on the default ribbon (lives in advanced-only flyout).
- Live joint sampling beyond the existing browser preview (no in-SW dynamic playback).
- VS-Code-style dockable WPF panel (Approach B). Rejected during brainstorming.

## 3. Approach: Hybrid (keep proven core, redo UI)

| Layer | Decision |
|---|---|
| `Sw2gzPipeline`, `RobotModel`, writers (URDF/SDF/launch/yaml), math (`PoseMath`, `SwToRosRotation`, anchors), preview server, mesh tessellator, golden tests | **KEEP** — proven, 605 tests green |
| Wizard PMP (`Sw2gzExportPmp` + linear `Mode→Links→Joints→Review`) | **DELETE** |
| Ribbon (`SwAddin`) | **REWRITE** — 3-mode tab, 4 clusters |
| `Sw2gzExportConfig` schema | **EVOLVE** — split into mode-scoped sub-objects |
| Per-panel PMPs (~12 new) | **NEW** |
| Coord auto-default | **NEW** — internal detection, no user pick by default |
| Plug-and-play stack writers (ros2_control, bridge, clock, RSP, env-vars) | **EXTEND** existing writers; fill the 60% gap |

## 4. Ribbon layout (one `SW2GZ` tab, 4 clusters)

```
[Common: Mode | Preview | Export]            (Coord hidden in advanced)
[Robot:  Links | Joints | Inertia | Sensors | Actuation | Stack]
[World:  Ground | Assets | Physics | Scene]
[Asset:  Body | Surface]
```

Mode toggle (pill: `Robot | World | Asset`) sits in the Common cluster. Non-active mode clusters hide via `OnEnableCallback`. Panel button labels are short (one-word) with optional sub-label showing current count or summary (e.g. `Joints / 2`, `Actuation / ros2_ctl`).

Mockup of record: `.superpowers/mockup/ribbon.html`.

## 5. Doc-attached config schema

Single SW Attribute feature **`SW2GZ Export Configuration (v1)`**, DataContract XML. Tree shape:

```
Sw2gzDoc
├─ Mode: Robot | World | Asset
├─ Coord { UpAxis, FwdAxis, AutoDetected: bool }   // hidden by default
├─ Robot? {
│    Links[] { Name, PartPaths[], InertiaSource }
│    Joints[] { Name, Parent, Child, Type, AxisPick, Limits, Dynamics }
│    Sensors[] { Kind, ParentLink, Pose, UpdateRate, KindSpecific{} }
│    Actuation { UseRos2Control, PerJointController[], MobileBasePreset }
│    Stack { RSP, JSB, Bridge, ClockBridge, UseSimTime }
│  }
├─ World?  { Ground, Assets[], Physics, Scene, SphericalCoords? }
└─ Asset?  { Body, Surface, Pose }
```

The legacy `URDF Export Configuration (v1.4)` attribute is **read-only-once for migration**, then ignored. New writes go only to `SW2GZ Export Configuration (v1)`.

## 6. Coordinate frame — automatic by default

**Default behaviour (no UI):** at export time the pipeline applies the SW→ROS rotation internally without prompting:

- URDF Robot mode: rotation baked into spawn `-R -P -Y` in the generated launch (REP-105 path — robot's `base_link` is the URDF root). Equivalent `world_to_base` joint-origin path remains as a code branch but is not exposed.
- SDF World mode: rotation premultiplied into each `<include><pose>` so an asset's SW-assembly pose ends up correctly oriented in the ROS-axis world frame. Premultiplication is `pose_world = R_sw_ros * pose_sw_assembly`.
- SDF Asset mode: rotation baked into spawn `-R -P -Y` in the launch.

**Resolution rule (no detection):** assume the canonical SW orientation (Y-up, X-fwd) and emit the corresponding `SwToRosRotation.Build(up=+Y, fwd=+X)` rotation. This is the orientation 99% of SW assemblies ship with, so no per-doc inspection is needed. Users with non-canonical assemblies open the advanced override.

**Advanced override:** an advanced-only Coord panel button (off-ribbon by default; surfaced via Common-cluster overflow / right-click context) lets the user pick `(up, fwd)` if their SW model deviates from the canonical orientation. Override is sticky in the doc-attached config; default is `AutoDetected=true`.

This kills the existing `Sw2gzExportConfig.SwUpAxis/SwForwardAxis` user-pick fields on the default code path.

## 7. Mode pipelines

`Sw2gzPipeline.Run` is decomposed:

```
Sw2gzPipeline.Run(outputDir, config)
  ├─ ValidatePreflight(...)        // keep — path / MAX_PATH / writability
  ├─ WalkAssembly(...)             // keep
  ├─ ResolveCoord(config)          // NEW — auto unless overridden
  └─ switch(config.Mode):
        Robot → RobotPipeline.Run(...)
        World → WorldPipeline.Run(...)
        Asset → AssetPipeline.Run(...)
```

Each mode-pipeline owns its directory layout, file list, and per-mode writers. Shared writers (DAE, STL, materials, package.xml, CMakeLists, ament_cmake) stay in `SW2GZ.Write`. Each mode-pipeline is < 300 lines and independently testable.

### 7.1 RobotPipeline

Files emitted into `<outputDir>/<pkg>_ws/src/<pkg>/`:

```
urdf/<pkg>.urdf.xacro
urdf/inc/materials.xacro
urdf/inc/ros2_control.xacro       ← when Actuation.UseRos2Control
urdf/inc/gz.xacro                  ← gz plugins (gz_ros2_control + sensors)
config/controllers.yaml            ← per-joint controller + JSB + diff_drive preset
config/ros_gz_bridge.yaml          ← /clock + sensor topics + joint states
worlds/empty.sdf
launch/gz_sim.launch.py            ← composes world+spawn+RSP+bridge+controller_spawner
meshes/<link>.dae + <link>_collision.stl
package.xml, CMakeLists.txt, README.md, .gitignore
```

Launch composition includes:
- `gz_sim` server
- `ros_gz_sim create` to spawn the model with `-R -P -Y` carrying the SW→ROS rotation
- `robot_state_publisher` with `use_sim_time:=true`
- `parameter_bridge` from `ros_gz_bridge` config
- `controller_manager` spawner chain: JSB first, then per-joint controllers

### 7.2 WorldPipeline

Files emitted into `<outputDir>/<pkg>_ws/src/<pkg>/`:

```
worlds/<pkg>.sdf                   ← physics, scene, light, gui plugins, includes
models/<ground_name>/{model.config, model.sdf, meshes/}
models/<asset_name>/{model.config, model.sdf, meshes/}    ← per asset
launch/<pkg>.launch.py
package.xml, CMakeLists.txt, README.md
```

The world SDF carries `<physics>/<gui>/<light>/<scene>` from the Physics + Scene panel config, then `<include>` blocks for each asset model with their asm-frame pose baked in (after SW→ROS rotation).

### 7.3 AssetPipeline

Files emitted into `<outputDir>/<pkg>_ws/src/<pkg>/`:

```
models/<pkg>/{model.config, model.sdf, meshes/}
worlds/empty.sdf
launch/<pkg>.launch.py
package.xml, CMakeLists.txt, README.md
```

Launch spawns the asset into an empty world at the user's chosen pose.

## 8. Modularity boundaries

Per the spec self-review later: each unit should have one clear purpose, communicate through well-defined interfaces, be testable independently. Concrete boundaries:

- **`SW2GZ.UI.Ribbon.*`** — one file per cluster (`CommonCluster`, `RobotCluster`, `WorldCluster`, `AssetCluster`). Each registers its commands with `SwAddin`. SwAddin orchestrates only.
- **`SW2GZ.UI.Pmp.*`** — one file per panel PMP (~12 files: `LinksPmp`, `JointsPmp`, `InertiaPmp`, `SensorsPmp`, `ActuationPmp`, `StackPmp`, `GroundPmp`, `AssetsPmp`, `PhysicsPmp`, `ScenePmp`, `BodyPmp`, `SurfacePmp`, `ExportPmp`, `PreviewPmp`). Each PMP knows ONE subtree node of `Sw2gzDoc` and edits it. No PMP reads another PMP's state.
- **`SW2GZ.URDFExport.RobotPipeline` / `WorldPipeline` / `AssetPipeline`** — pure orchestrators. Each ≤ 300 lines.
- **`SW2GZ.Math` consolidated:** single `PoseMath` (collapse `UI.ViewModels.PoseMath` → `Math.Rpy` helpers). One quaternion-from-rpy formula.
- **Coord auto-detection:** `SW2GZ.Build.Model.CoordAutoDetect.Resolve(swDoc, configOverride) → CoordinateConvention`. Pure, mockable.

## 10. Step-wise delivery — no big-bang

Implementation lands as **independent commits**, each leaving the test suite green and the Release DLL bootable in SolidWorks. No single commit touches more than one concern.

Proposed order (each step ≈ 1 PR-sized commit):

1. **Cleanup pass — dead code** (Section 9 deletes 1–5). No new features. Tests stay 605 green.
2. **Naming migration** — `sw2urdf` → `sw2gz` rename sweep. Mechanical.
3. **Math consolidation** — collapse dual `PoseMath`. Tests untouched.
4. **`Sw2gzDoc` schema evolution** — extend the existing `Sw2gzExportConfig` DataContract with mode-scoped sub-objects (`Robot?`, `World?`, `Asset?`). The existing flat fields stay readable during transition; the new tree is the source of truth for v2.1.0 writers. One-shot reader for the legacy `URDF Export Configuration (v1.4)` attribute, then ignored.
5. **Coord auto-detect** — `CoordAutoDetect.Resolve`. Pipeline call-site uses it; old `SwUpAxis/SwForwardAxis` fields move to advanced-only override. Default config has them unset.
6. **Pipeline split** — `RobotPipeline`, `WorldPipeline`, `AssetPipeline` extracted from monolithic `Sw2gzPipeline.Run`. Behaviour byte-identical (goldens stay green).
7. **Plug-and-play stack gap fills** — ros2_control block, gz_ros2_control plugin, controllers.yaml, ros_gz_bridge.yaml + `/clock`, RSP + JSB + `use_sim_time` wiring, env-var paths. Each writer in its own commit with golden update.
8. **Ribbon rewrite** — `SwAddin` registers Mode + Preview + Export + per-cluster panels. Old `Sw2gzExportPmp` linear wizard deleted. Each new per-panel PMP added in its own commit, gated behind the ribbon command that opens it.
9. **PMP wave** — one commit per PMP (~12), in the order: Links, Joints, Inertia, Sensors, Actuation, Stack, Ground, Assets, Physics, Scene, Body, Surface.
10. **Preview-dialog adjustment** — `PreviewServer` keeps the browser preview; `PreviewDialog` reads coord-auto-resolved URDF; remove dead `PreviewResult` fields.

Stop conditions per step:
- All tests green (`dotnet test` returns 0).
- DLL builds (`bin\Release\SW2GZ.dll` written fresh).
- The add-in still loads in SolidWorks without surfacing an error.

## 11. Error handling

Existing patterns preserved:
- **Pre-export failures** (material missing, MAX_PATH overrun, non-writable target, invalid joint axis pick) → `Sw2gzExportException`, NO output dir created.
- **Post-write validation** → `ValidationReport` returned with warnings; only errors are fatal.
- **COM boundary catch-all** at ribbon command entry-points.
- **Per-run log** (`sw2gz_export.log`) written into the workspace summarising mode, config, link/joint/sensor counts, warnings, errors.

PMP cancel rolls back the in-memory `Sw2gzDoc` to the pre-PMP-open snapshot; PMP OK commits to the doc attribute via `Sw2gzConfigSerialization.Save`.

## 13. Success criteria

v2.1.0 is done when:

1. SolidWorks ribbon shows the `SW2GZ` tab with the four clusters from §4.
2. A Robot-mode export of `delta_arm.SLDASM` produces a colcon-buildable package that `ros2 launch <pkg> gz_sim.launch.py` runs end-to-end: world loads, robot spawns upright (coord auto applied), `/joint_states` published, controllers respond to `ros2 topic pub`.
3. A World-mode export of an assembly with ground + 3 props produces a Gz world that loads with the props at their SW assembly poses (after auto SW→ROS rotation).
4. An Asset-mode export of a single part produces a model that spawns into an empty world at the picked pose.
5. The brainstorming-cleanup list (§9) is fully landed.
6. All `sw2urdf` / `URDF Export` identifiers have migrated to `sw2gz` / `SW2GZ Export` naming (excluding URDF/XML output strings, which the spec requires).
7. Test suite ≥ 605 + new tests, all green. Release DLL boots in SolidWorks.
