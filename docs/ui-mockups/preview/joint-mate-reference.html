SW Mate → URDF / SDF / ros2_control

Comprehensive mapping of every SOLIDWORKS mate type the exporter cares about. Drives AutoJointResolver.Resolve, the Create-Robot Joints step, and the preview's Mates → Joints panel. Status column shows v2.1.0 coverage.

URDF joint types (target schema)

revolute

1-DOF rotation about axis with lower/upper limits. Most common arm joint.

continuous

1-DOF rotation, no limits. Wheels, spindles, anything that rolls freely.

prismatic

1-DOF translation along axis with limits. Linear actuators, sliders.

fixed

0-DOF rigid weld. Default fallback when the mate carries no motion.

floating

6-DOF unconstrained (3 trans + 3 rot). Rarely useful; usually a modelling smell.

planar

3-DOF in-plane motion (2 trans + 1 rot). Some packages don't honour it.
SDF/Gz adds: revolute2 (universal joint, 2-axis), ball (3-DOF spherical, no limits), screw (helical, rot+lin coupled by pitch), universal (2-axis perpendicular), gearbox (mimic with reduction). The pipeline picks the URDF subset for RobotPackage mode and the SDF superset for SdfModel / SdfWorld mode.

AutoJointResolver decision flow (v2.1.0)

Resolve() per mate, in this order:
  • Pre-check — both picked entities present and non-null. If not → mark AMBIGUOUS and skip.
  • Switch on mate.Type:
    • swMateCONCENTRIC → TryExtractCylinder; if ok and has angle/distance limit, classify as revolute/prismatic; else continuous.
    • swMateANGLE / LimitAngle → TryExtractPlane ×2 → axis = cross(parent.n, child.n) → revolute.
    • swMateDISTANCE / LimitDistance → TryExtractPlane → axis = parent.n → prismatic.
    • swMateLOCK → no geometry, fixed.
    • default → no extraction, fixed (safety net).
  • Post — limits, effort/velocity defaults (100 N·m, 1 rad/s when SW didn't specify), axis re-expression into child link frame.
